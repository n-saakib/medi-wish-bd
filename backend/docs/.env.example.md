# `.env.example`

This template lists the backend database and authentication settings used for local development and integration tests. Copy it to `backend/.env` and fill in local credentials; the copied file is ignored by Git.

| Setting group | Purpose |
| --- | --- |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD` | Spring Boot runtime connection to the development database, normally `medi_wish_dev`. |
| `TEST_DB_HOST`, `TEST_DB_PORT`, `TEST_DB_NAME`, `TEST_DB_USERNAME`, `TEST_DB_PASSWORD` | Guarded integration-test connection, fixed to `medi_wish_test`; tests create and remove only a run-owned schema. |
| `APP_CORS_ALLOWED_ORIGINS` | Explicit browser origins allowed for credentialed CORS; wildcard origins are rejected. |
| `APP_AUTH_JWT_SECRET` | Base64 HMAC signing secret with at least 32 decoded bytes; required at runtime. Startup fails without quoting the value when it is missing, not Base64 or too short. |
| `APP_AUTH_MFA_SECRET_KEY` | Base64 of exactly 32 random bytes; the AES-256-GCM key that encrypts staff authenticator seeds. Required at runtime, including for the first-Admin command. Keep it separate from the JWT secret, and never rotate it without re-enrolling staff, because existing seeds could no longer be decrypted. The template shows a PowerShell generator. Startup fails without quoting the value when it is missing, not Base64 or not 32 bytes. |
| `APP_AUTH_COOKIE_SECURE` | Secure flag for the refresh and CSRF cookies; keep `true` for hosted environments. `false` is accepted only when at least one profile is active and every active profile is `local` or `test`; otherwise startup fails. |

The dummy password verifier used for unknown-identifier comparisons is generated at startup, so it has no setting.

The integration harness reads process environment variables first, JVM system properties second and this backend-local `.env` file last. Spring Boot itself still expects runtime `DB_*` values in the process environment when the application is started; set `SPRING_PROFILES_ACTIVE=local` explicitly when running a local HTTP configuration with `APP_AUTH_COOKIE_SECURE=false`.

## Start the backend locally

From `backend/` in PowerShell, load the ignored file into the current process, explicitly select the local profile, and start Spring Boot:

```powershell
Get-Content .env | ForEach-Object {
  if ($_ -match '^\s*([A-Z][A-Z0-9_]*)=(.*)$') {
    $null = Set-Item -Path "Env:$($matches[1])" -Value $matches[2]
  }
}
$env:SPRING_PROFILES_ACTIVE = 'local'
# Set false only for local HTTP testing; retain true when using HTTPS.
$env:APP_AUTH_COOKIE_SECURE = 'false'
.\mvnw.cmd spring-boot:run
```

The database and auth settings in `.env` must be filled before startup. The profile is process-scoped; opening a new shell requires loading the file again. In another PowerShell window, verify the safe public probes with `Invoke-RestMethod http://127.0.0.1:8080/actuator/health/liveness` and `Invoke-RestMethod http://127.0.0.1:8080/actuator/health/readiness`. Stop the app with `Ctrl+C`; never print or commit `.env` values.


Ticket 15 documents APP_STORAGE_PROVIDER=local, absolute APP_STORAGE_LOCAL_ROOT and environment-specific APP_STORAGE_NAMESPACE. Test namespaces start with test- and serving startup validates all settings.


## Ticket 05 recovery

APP_AUTH_RECOVERY_CODE_KEY documents an independent Base64 32-byte HMAC secret. APP_MAIL_TRANSPORT defaults to disabled; directory capture and its directory setting are for local/test profiles.

## Generate independent keys on Windows

Run this block separately for each required secret. It works in Windows PowerShell 5.1 and newer; the static `GetBytes(int)` convenience API is unavailable in Windows PowerShell 5.1. Copy the resulting value into the appropriate local environment setting and keep it out of logs and source control. Recovery must use its own key, distinct from JWT and MFA.

```powershell
$recoveryKeyBytes = New-Object byte[] 32
$recoveryKeyGenerator = [Security.Cryptography.RandomNumberGenerator]::Create()
try {
    $recoveryKeyGenerator.GetBytes($recoveryKeyBytes)
    [Convert]::ToBase64String($recoveryKeyBytes)
} finally {
    $recoveryKeyGenerator.Dispose()
}
```
