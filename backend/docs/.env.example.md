# `.env.example`

This template lists the backend database and authentication settings used for local development and integration tests. Copy it to `backend/.env` and fill in local credentials; the copied file is ignored by Git.

| Setting group | Purpose |
| --- | --- |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD` | Spring Boot runtime connection to the development database, normally `medi_wish_dev`. |
| `TEST_DB_HOST`, `TEST_DB_PORT`, `TEST_DB_NAME`, `TEST_DB_USERNAME`, `TEST_DB_PASSWORD` | Guarded integration-test connection, fixed to `medi_wish_test`; tests create and remove only a run-owned schema. |
| `APP_CORS_ALLOWED_ORIGINS` | Explicit browser origins allowed for credentialed CORS; wildcard origins are rejected. |
| `APP_AUTH_JWT_SECRET` | Base64 HMAC signing secret with at least 32 decoded bytes; required at runtime. |
| `APP_AUTH_DUMMY_PASSWORD_VERIFIER` | Valid Argon2 verifier used for indistinguishable unknown-identifier comparisons; required at runtime. |
| `APP_AUTH_COOKIE_SECURE` | Secure refresh-cookie flag; keep `true` for hosted environments and use `false` only as an explicit local HTTP-test override. |

The integration harness reads process environment variables first, JVM system properties second and this backend-local `.env` file last. Spring Boot itself still expects runtime `DB_*` values in the process environment when the application is started.
