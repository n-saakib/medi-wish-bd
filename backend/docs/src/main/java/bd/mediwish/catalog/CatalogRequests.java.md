# CatalogRequests

Catalog-local JSON and query binding. JsonNode input is converted to typed request records only after exact object properties and scalar types are checked. This prevents mass assignment and Jackson scalar coercion while preserving existing authentication binding behavior. Invalid values raise InvalidCatalogException or InvalidMoneyException; ordinary responses contain no submitted value or field diagnostic.

CategoryCreate requires canonical UUID text and string name. ProductCreate requires UUID, exact ProductKind and typed catalog fields; medicine genericName/dosageForm are required strings. Optional text may be omitted or null. Active, version, money and other unknown properties are forbidden on create, and Product fields always carry active=false.

CategoryUpdate accepts only name, active and version. ProductUpdate accepts catalog text/category fields, requireValidation, active and version, excluding id/kind/money. Required booleans cannot be null or coerced. Generic/dosage fields have nullable string shape on update because the service owns the stored immutable kind. Version requires an integral nonnegative JSON number within a signed long; decimals, strings, missing/null values and overflow are refused.

PricingUpdate accepts only sellingPrice, mrp and version. Money must be JSON text accepted by Money.parse: exact positive BDT without rounding or floating-point conversion. Omitted/null MRP is permitted; empty MRP, JSON numbers, signs, exponents, excessive precision and overflow are refused. Price relationship validation remains in ProductService.

Known query values are parsed locally before service calls: page defaults to 0 and is nonnegative; size defaults to 20 and is 1-50; booleans accept true/false only. includeInactive defaults true and reviewRequired false. ProductStatus names are exact, category UUIDs use canonical form with either hex case, and q accepts empty text but at most 100 characters. ProductService owns literal substring escaping. Unknown query parameters are ignored. Duplicate JSON member rejection remains outside the accepted Ticket 14 scope.

Duplicate JSON member rejection remains excluded by the accepted T1 contract. CatalogRegressionIT characterizes the pinned Spring Boot 4.1.1 / Jackson 3.1.5 HTTP JsonNode binding: the last occurrence wins before catalog shape/type validation. A repeated name retains the final string; a final boolean is still rejected as bounded INVALID_REQUEST. No shared mapper strictness or authentication behavior is changed. The shared service page guard additionally rejects offsets beyond the signed integer JPA limit.
