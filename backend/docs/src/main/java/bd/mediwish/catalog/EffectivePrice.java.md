# `EffectivePrice.java`

Immutable current-price snapshot with ten record components: `UUID productId`, `Money sellingPrice`, optional `Money mrp`, `Money price` (payable price), `BigDecimal saving`, `UUID discountId`, `DiscountTargetType discountTarget`, `DiscountKind discountKind`, `BigDecimal discountValue`, and `LocalDate pricedOn` (captured Dhaka business date). `PriceCalculator` supplies null for all four Discount components when none applies, with zero saving and the stored Selling Price as payable price.

The record retains value components, never Product or Discount entities. `Money` is immutable but has no `equals`/`hashCode`; Product price accessors construct new Money instances. Record `equals` therefore does not establish monetary value equality. Compare snapshot components using `Money.compareTo` or rendered amounts and numeric BigDecimal comparison. Captured values survive later Discount edits or ends.

`CurrentPrices` supplies snapshots through public read-only transactional methods: `forProduct` returns empty for missing/unpriced Products; `forActiveProduct` also excludes inactive Products and serves anonymous reads; `forProducts` queries Discount candidates once for a priced page and omits unpriced Products. Methods join a caller transaction or open one when absent; newly opened reads use repeatable-read isolation. The overload accepting `today` lets Product detail use one date for pricing and history.

Cart consumers in Tickets 23/24 must read current prices from `CurrentPrices`. Ticket 25 Order acceptance must copy `price`, `saving`, `discountId`, `discountKind` and `discountValue` into Order-line columns and never join live Discounts afterwards. Ticket 16 has no Cart or Order tables: its boundary proves Discount commands write only `discounts`/`discount_changes`, snapshots have immutable components and survive Discount edits, and Product price changes recompute from stored Selling Price. The persisted Order-snapshot regression remains downstream Ticket 25 work.
