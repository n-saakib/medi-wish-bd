# `DiscountHistory.java`

Derives Discount transitions for staff Product detail without persisting Product changes. Source selection uses Discounts targeting the Product or its current Category, including promotions that lose the price comparison. After a Category move, the history reflects the new Category's events, not past membership. `DiscountRepository.findHistory` excludes future starts and ends strictly before the start instant before taking at most 20 source Discounts, ordered by latest event descending, then id.

`forProduct(productId, categoryId)` captures the Dhaka date; its overload accepts the request's captured date. Each makes one history query, batches usernames for distinct non-null ending actors when present, then delegates to pure `entries(discounts, usernames, today)`. A `DISCOUNT_STARTED` event occurs at Starts 00:00 Asia/Dhaka with no actor. An explicit end produces `DISCOUNT_ENDED` at `endedAt` with the ending Admin's current username; otherwise an elapsed inclusive Ends date produces an end at the following Dhaka midnight with no actor. Scheduled Discounts and those explicitly ended before starting produce no events.

Every derived event carries `HistoryDiscount {targetType, kind, value}` using the Discount's current kind/value. An edit of an already-started promotion is not replayed in these events; `discount_changes` retains the full audit. `renderValue` emits whole percentages without decimal scale and flat amounts as two-place Money strings.

`ProductService.view` merges up to 20 stored changes with derived events, sorts by `occurredAt` descending with stored rows first at equal instants, and returns the latest 20 entries. Stored rows have `discount: null`; derived entries leave the ordinary Product field-change values null. The Product list and public pricing route do not expose this history. `DISCOUNT_STARTED` and `DISCOUNT_ENDED` are read projections; the database Product-change type constraint refuses their persistence.
