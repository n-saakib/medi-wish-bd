# `PublicCatalogService.java`

Read-only public catalog projections. `categories` maps the ordered listable-category query; `categoryPage` verifies an active category, checks the listed-item count before calculating the 24-item page, batches position-zero `PublicCatalogImage` values and current prices, and skips any Product whose price snapshot is unexpectedly missing (plan step 5: never show an unpriced offer). That case is unreachable today, because the listed query and `CurrentPrices` both require a selling price; if it ever occurred, `totalItems` and the pager would still count the skipped Product, so a page would show fewer than 24 cards. `product` reads one active priced Product, ordered images and its current price. Product details keep the Product readable when its Category is inactive, but omit that Category from the public projection. Equipment never exposes medicine-only generic-name or dosage-form values.

Category pages and details run in read-only `REPEATABLE_READ` transactions so Product rows, counts, images, category state and discount candidates share one snapshot. The nested `CurrentPrices.forProducts` call joins that transaction. The service does not create or update schema objects.
