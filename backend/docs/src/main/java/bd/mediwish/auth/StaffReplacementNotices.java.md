# `StaffReplacementNotices.java`

Post-commit replacement notice coordinator. `notifyReplacement(userId)` reads the User without a lock and sends to every verified contact: mobile through `SecurityNotifier`, email through Ticket 05's `EmailTransport`. Unverified contacts never reach either adapter. Disabled mail configuration is `NOT_CONFIGURED`, because its no-op transport cannot confirm delivery.

Both channels run independently on the owned virtual-thread executor under one shared configured deadline (one to five seconds). Exceptions in one channel do not suppress the other. Timeout and interruption cancel unfinished work. The combined outcome is `SENT` if any channel delivered, otherwise `FAILED` if any failed, otherwise `NO_VERIFIED_CONTACT` if no contact was verified, otherwise `NOT_CONFIGURED`. Caller interruption is preserved.

Externalized text uses an English `Asia/Dhaka` timestamp with `d MMM yyyy, h:mm a`; email uses `mail.staffAuthenticatorReplaced.subject` and `.body`, and `EmailKind.STAFF_AUTHENTICATOR_REPLACED`. No contact or message text is logged. Every outcome maps to its `MFA_REPLACEMENT_NOTICE_*` event through `SecurityAuditLog.recordInNewTransaction`, so the audit commits independently after replacement. The caller interrupt is cleared for audit connection acquisition and restored afterwards. Audit failure never changes the delivery result or hides new codes. The recovery service invokes this only after its replacement transaction returns. `close()` interrupts executor work at shutdown. Real providers and durable retry remain deployment/Ticket 26 work.
