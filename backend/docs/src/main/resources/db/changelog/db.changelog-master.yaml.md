# `db.changelog-master.yaml`

Source: [`src/main/resources/db/changelog/db.changelog-master.yaml`](../../../../../../src/main/resources/db/changelog/db.changelog-master.yaml)

## Purpose and reasoning

This is the Liquibase changelog entry point configured by `application.yaml`. Its initial changeset records the application baseline, the original registration table is retained as applied history, changeset `004-shared-users-and-roles` migrates it to the shared User table with persisted role assignments, and one unique case-insensitive expression index now both enforces unique optional email and serves the email lookup. Changeset 006's exact-match index remains in history and is removed by the later forward-only cleanup. Starting with tagged, append-only changesets gives later stories a stable migration history and lets tests prove that restart does not reapply it.

## Changesets

| Element | Behavior and use case |
| --- | --- |
| `id: 001-foundation` | Stable identifier for the initial baseline changeset. Once applied, do not edit it; append a new changeset for schema changes. |
| `author: medi-wish` | Identifies the owning application in Liquibase history. |
| `tagDatabase: application-baseline` | Tags the database at the foundation boundary for diagnostics and future rollback/release workflows. |
| `id: 002-customers` | Creates durable Customer identity data with unique username/mobile constraints, password verifier storage, optional email, mobile-verification state and creation timestamp. Its original database defaults remain unchanged for Liquibase checksum stability. |
| `id: 003-customer-java-owned-values` | Removes the `id` and `created_at` database defaults after the original changeset, leaving the Java constructor as the single application write-path owner without editing an applied changeset. |
| `id: 004-shared-users-and-roles` | Renames the applied identity table to `users`, creates the `user_roles` assignment table with a foreign key and composite primary key, and backfills existing rows with the `CUSTOMER` role. |
| `id: 005-user-password-sessions` | Adds durable session families and one-use refresh generations with UUID keys, `TIMESTAMPTZ` lifecycle fields, a lowercase SHA-256 digest bounded to `VARCHAR(64)`, family/user and session/generation uniqueness/index boundaries, and cascading foreign keys. |
| `id: 006-user-email-lookup` | Historically adds a non-unique B-tree index on `users.email`. Duplicate email remains allowed; the later 008 cleanup removes this index after sign-in adopted case-insensitive lookup. |
| `id: 007-user-email-case-insensitive-lookup` | Adds a non-unique B-tree expression index on `upper(users.email)` for case-insensitive email sign-in. It preserves all stored email values and does not introduce email uniqueness. |
| `id: 008-drop-unused-exact-email-index` | Drops the unused `idx_users_email` index without rewriting applied changesets; the expression index remains to support the case-insensitive lookup. |
| `id: 009-unique-user-email` | Its `sqlCheck` precondition counts non-null emails that repeat ignoring case and expects none. On a match it halts (`onFail: HALT`) with a message that names the rule but no address, and changes nothing; the operator resolves the duplicates and reruns it. Otherwise it drops `idx_users_email_upper` and, through `createIndex` with a `computed` column, creates the unique `uk_users_email_upper` on `upper(email)`, which allows any number of NULL emails. |
| `id: 010-staff-mfa` | Staff MFA and first-Admin provisioning (Ticket 06). Creates `staff_mfa_factors` (cascading User FK, `ck_staff_mfa_factors_status` for `PENDING`/`ACTIVE`/`REVOKED`, `BYTEA` ciphertext and nonce, `last_used_step` default `-1`) with the partial unique indexes `uq_staff_mfa_active` and `uq_staff_mfa_pending` on `user_id`, so a User has at most one active and one pending factor; `staff_mfa_backup_codes` (cascading factor FK, `idx_staff_mfa_backup_codes_factor`); `staff_mfa_throttle` (User ID primary key and cascading FK); `staff_bootstrap` (`SMALLINT` key with `ck_staff_bootstrap_singleton` `CHECK (id = 1)`, `super_admin_user_id` FK `ON DELETE SET NULL`); and `security_audit_events` (no free-text column, subject FK `ON DELETE SET NULL`, `idx_security_audit_events_subject` on `(subject_user_id, occurred_at)`). Adds nullable `mfa_factor_id` (FK to `staff_mfa_factors` `ON DELETE SET NULL`) and `mfa_verified_at` to `user_sessions`; existing sessions keep both `NULL`, which is a password-only session. |
| `id: 011-staff-role-changes` | One role per User (`user_roles.user_id` primary key) with deferred `user_role_required` triggers, `users.roles_version` and the `user_role_changes` audit table (Ticket 08). |
| `id: 012-user-profile` | Adds nullable `users.full_name` and `users.date_of_birth`, non-null `profile_version` default 0, and non-null `account_state` default `ACTIVE` with `ck_users_account_state` allowing `ACTIVE` or `CLOSURE_REQUESTED`. Creates `user_mobile_changes` with UUID primary key, unique `user_id`, replacement number and request time. Its User FK cascades deletion. Existing Users retain empty optional profile fields and start active at version zero. |
| `id: 013-catalog` | Category, Product and Product-history tables with exact `NUMERIC(9,2)` amounts, kind and pricing checks and restrictive foreign keys (Ticket 14). |
| `id: 013-catalog-finite-money` | Upper bounds on nullable Product prices, so only finite 0.01–9999999.99 amounts are stored (Ticket 14). |
| `id: 014-role-required-search-path` | Pins `user_role_required()` to the schema it was migrated into (Ticket 08 fix forward). |
| `id: 018-staff-mfa-recovery` | Nullable session replacement-factor binding and backup-code consuming-session ID, replacement-factor FK and consistency checks. Existing rows retain nulls. |

Liquibase owns schema evolution while Hibernate is configured only to validate. User generates its UUID identifier and creation timestamp in the Java constructor; changeset `003-customer-java-owned-values` removes the original defaults without changing an applied changeset's checksum, and `004-shared-users-and-roles` preserves existing identities while moving them to the shared User vocabulary. The changelog is applied in the configured schema, including the unique schema created by the integration harness.

The Ticket 03 session tables retain consumed refresh generations through family expiry so replay can be distinguished from an unknown token; cleanup is intentionally deferred. The raw refresh value is never a schema field.

The nullable email column is unique ignoring case since changeset 009 (Ticket 03.03 D1), so email sign-in matches at most one User through the same `upper(email)` index. Schema history remains append-only, and no migration normalizes stored email values.

Changeset 010 changes no existing row. Authenticator seeds are stored only as AES-256-GCM ciphertext and backup codes only as Argon2 verifiers; no plain seed, code or username is a schema field.

Changeset 012 adds an explicit optimistic edit version and a single pending mobile replacement per User. It stores the replacement separately until verified activation; no OTP or verification secret is persisted by this changeset. The new User defaults preserve existing accounts without rewriting their identity data.

Changeset `013-catalog` appends category, Product and Product-history tables with UUID keys. A case-insensitive category-name unique index and explicit CHECK constraints enforce Product kind, positive exact `NUMERIC(9,2)` amounts, medicine/equipment field shape and active-implies-priced. Category and history foreign keys restrict deletion; staff actor references become NULL if their User is removed. Category/name and recent-history indexes support bounded staff reads. No inventory schema is introduced.

## Verification

`HealthIT` checks that the changelog is applied, survives an application restart and does not reapply when existing data is present. `LegacyUserMigrationIT` migrates legacy rows through 009 and proves that duplicate legacy emails halt 009 with the rows unchanged; `RegistrationIT` and `SignInIT` exercise the unique index. `StaffMfaMigrationIT` applies 001–009, refreshes an existing Customer session after 010 (`mfa: NOT_REQUIRED`, no evidence) and checks the status check, the one-active and one-pending indexes and the bootstrap singleton. `DependencyCompatibilityIT` repeats the migration and restart check with the optional integrations enabled.

Changeset `011-staff-role-changes` first halts on unknown role values. It retains each User's highest role and fills CUSTOMER for roleless legacy rows, replaces the composite role primary key with user_id alone and checks the four names. Deferred constraint triggers on User insertion/id change and role deletion/user-id change ensure every committed User has a role, while allowing transactional delete/insert replacement and cascading User deletion. The trigger's error names only user_role_required. It adds roles_version default zero and the bounded old/new-role audit table with nullable actor/target foreign keys ON DELETE SET NULL, unequal valid-role checks and a target/time descending index. Conversion leaves sessions, bootstrap and existing audit untouched. StaffRoleMigrationIT exercises real upgrade fixtures, halt safety and commit-time constraints; StaffRoleMappingIT verifies compatibility with Hibernate's collection replacement.
`ProfileMigrationIT` verifies the Ticket 11 defaults on existing Users, the account-state check and one-pending-row uniqueness/FK behavior after 012. `UserProfileIT` and `ConcurrentProfileIT` exercise the version and duplicate-contact boundaries against PostgreSQL.

Appended `013-catalog-finite-money` preserves applied `013-catalog` history and adds upper bounds to nullable Product prices. Combined with the original positive checks, these guards permit finite `0.01`–`9999999.99` values and reject PostgreSQL numeric NaN; null remains permitted for unpriced Products. Keeping the lower-bound constraints preserves specific zero/negative refusal diagnostics. `CatalogMigrationIT` verified NaN refusals, the maximum finite positive control and unchanged pre-catalog User/session snapshots in the 2026-10-07 guarded gate; final cumulative verification remains pending.

Changeset `014-role-required-search-path` fixes 011 forward. The `user_role_required()` function names `users` and `user_roles` without a schema, so it resolved them through the writing session's search path: an operator session without the application's schema failed with `relation "users" does not exist`, or checked same-named tables in another schema. A `DO` block runs `ALTER FUNCTION <current_schema>.user_role_required() SET search_path = <current_schema>, pg_temp`, using the schema Liquibase migrates into, so the check always reads its own tables and temporary tables cannot shadow them. The function body and triggers are unchanged. `StaffRoleMigrationIT` writes from a `pg_catalog`-only session with schema-qualified SQL: a roleless User and deleting the only role are still refused with the `every User needs a role` check violation, and a delete-then-insert role replacement commits.

## Ticket 15 image storage

Append-only Liquibase schema history. Changeset015 adds metadata-only product_images and retired_product_image_ids, with canonical object ownership, PNG/JPEG, 3 MiB, 4096 dimensions, SHA-256 and alt constraints. Deferred unique positions0–7 enforce an eight-image cap. Existing changesets stay unchanged. Forward fixes use a new changeset; backout removes namespace objects before dropping metadata tables.
Changeset 016-discounts adds discounts and immutable discount_changes audit snapshots plus candidate/date/history indexes. Exactly-one target/value, finite amount, whole 1-99 percent, valid dates and restrictive Product/Category references are checked in PostgreSQL. Existing Product rows and columns remain unchanged. Recovery uses a new forward-fix changeset, never edits applied 016; a reviewed rollback drops discount_changes then discounts only after confirming no consumer references either table. DiscountMigrationIT rehearses empty-schema creation and upgrade with existing Product versions/timestamps preserved.
Changeset 017-saved-addresses adds owner-scoped saved addresses and owner/time-only successful-change rows, named composite/log keys, cascading User foreign keys, bounded field checks, one-default partial uniqueness and owner/order and owner/time indexes. No cap or allowance values enter schema constraints and no table references saved_addresses.

Changeset 018 follows 017 without rewriting applied history. It requires replacement sessions to remain unverified and consumed codes to carry both a timestamp and presenting-session ID. The replacement-factor FK uses ON DELETE SET NULL; consumed_session_id has no FK so history may outlive its session. Existing factor indexes remain sufficient. Real PostgreSQL migration/upgrade verification is recorded separately.
