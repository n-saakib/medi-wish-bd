# UserServiceTest

Unit tests cover normalized shared-User registration, Customer-role assignment, optional and blank email handling, password-verifier storage, preservation of meaningful leading/trailing password whitespace, a taken username or a taken mobile rejected as a duplicate without saving or encoding the password (the check order is not pinned), and conversion of a bare PostgreSQL SQL-state `23505` exception into the bounded duplicate outcome at the service seam. Isolated boundaries accept normalized username lengths 3 and 50, nonblank password lengths 12 and 128, a nonblank 30-character mobile and a 320-character email under the current syntax check; separate cases reject lengths 2/51, blank or out-of-range passwords, blank/31-character mobile, malformed email and a 321-character email. No phone-format rule or stricter email grammar is added.
