# `src/storefront/CategoryNavLinks.tsx`

Source: [`src/storefront/CategoryNavLinks.tsx`](../../../src/storefront/CategoryNavLinks.tsx)

Client component that renders the first eight category destinations and an All categories link in a translated navigation landmark. Empty input produces no navigation. The links remain keyboard-accessible, and the horizontal bar scrolls within its own viewport on narrow screens.

The current-page mark comes from the rendered page, not the URL. `CurrentCategoryProvider` (mounted by the store layout around the bar and the page) holds one bar destination. `CurrentCategoryMark({ href, current })` declares its destination after mount and clears it on unmount; `current` is `page` (default) or `true`. The category directory (`/categories`) and page 1 of a category listing declare `page`; later listing pages and a Product page with an active category declare `true` for that category, because the bar link does not open the page being viewed. `CategoryNavLinks` gives the declared link that `aria-current` value and the design's `is-active` underline, so the state is shown by more than color. Marking the Product's category follows `ui-design/product.html` (`data-active`). A store not-found or error view renders no mark, so a 404 on a listed category's URL (for example `?page=99`) marks no category.

Design deviation (accepted trade-off, review M3): the mark is set in an effect, so it appears only after hydration. Server HTML, the pre-hydration paint and JavaScript-disabled readers show no current category, while the design renders `is-active` in markup. The layout cannot see whether the page will render or answer 404, so a server-side mark would mark a category on its own 404 page.
