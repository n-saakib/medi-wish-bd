# `src/lib/session.ts`

Source: [`src/lib/session.ts`](../../../src/lib/session.ts)

## Purpose

The browser session seam owns short-lived access-token state in module memory. It never persists the access token or exposes the opaque refresh-cookie value to application code.

## Interface

- `createSessionClient(options)` creates an injectable client with an injectable `fetch` dependency; its configured base URL remains private to the client.
- `projectUserIdentity(body)` validates and projects the shared public username/mobile/email fields. `projectSessionUser(body)` adds the required `mobileVerified` flag for session/profile responses.
- `readJsonResponse(response)` reads at most 16 KiB of JSON bytes, cancels an oversized stream without trusting `Content-Length`, and distinguishes malformed JSON (`INVALID_RESPONSE`) from body-read/abort failures (`REQUEST_FAILED`) without exposing underlying errors.
- `signIn(identifier, password)` posts the fixed login payload with `credentials: include`, validates a projected `SessionResponse`, and serializes its cookie mutation with refresh/logout operations.
- `restoreSession()` bootstraps CSRF and attempts one refresh, returning `null` for an unauthenticated session.
- `refreshSession()` rotates through the refresh-cookie endpoint, shares one in-flight request among callers in the same client, queues the cookie-mutating operation, and holds the shared exclusive Web Lock across CSRF bootstrap, refresh, and response validation when the browser exposes `navigator.locks`. Sign-in and sign-out use this same lock for their full credentialed request and response handling, preventing same-origin tabs from applying stale refresh-cookie mutations out of order. Browsers without Web Locks retain only per-client serialization, and separate frontend origins do not coordinate. If refresh fails while an access token is live, it clears that token and advances the session epoch so already-started authenticated responses cannot commit stale results.
- `authenticatedFetch(input, init?)` resolves the request URL against the session API base URL and requires its origin to match before adding the in-memory Bearer token. It snapshots the request once and clones it for each attempt, preserving a body-bearing request across its one refresh/retry after a `401`; it rechecks the URL origin before every attempt and uses one response-epoch guard for initial and retried body reads so stale session results cannot commit. A same-token `401` may advance the expected epoch once; a rejected retry clears that token and advances the session epoch. The native-`Response` form remains unchanged; an overload accepts an asynchronous response reader so callers can consume a body within the operation deadline.
- `signOut()` clears memory immediately, queues the CSRF-protected logout request behind earlier cookie mutations, and holds the shared Web Lock through CSRF bootstrap and the logout response when available; local logout remains effective on network failure. `clearSession()` invalidates both session results and queued cookie mutations. A retry that is still unauthorized advances only the session epoch, so a newer queued sign-in is not canceled.

CSRF bootstrapping receives a bounded nonce from `GET /api/auth/csrf`; the API still sets the non-HttpOnly `XSRF-TOKEN` cookie and validates the echoed `X-XSRF-TOKEN` header. Returning the nonce is necessary because the frontend and API use separate origins, so the frontend cannot read an API-origin cookie through `document.cookie`. Session/user responses are reconstructed from validated projections, public errors retain bounded code/message/status plus an optional bounded request ID, and session operations have a bounded timeout through body parsing when a response reader is supplied. Caller cancellation is composed with the timeout and maps to a bounded `REQUEST_FAILED`; while waiting for a shared refresh, cancellation promptly rejects only that authenticated request and leaves the shared refresh available to other callers. Malformed JSON remains `INVALID_RESPONSE`. A plain `Response` call preserves native body ownership, so its caller must use the response-reader overload when body consumption must share the deadline. Cookie-mutation calls capture a mutation epoch before queueing and reject before network dispatch if `clearSession()` invalidated them, preventing queued sign-ins/refreshes from reviving a cleared client. No localStorage, sessionStorage, IndexedDB, URL, console or durable application state is used for access credentials.

Session projections accept any positive integer `expiresIn`; no arbitrary one-day maximum is imposed. An off-origin authenticated destination fails with the generic request error before the fetch dependency is called or a Bearer header is created. String and `URL` inputs are fetched using their resolved URL; `Request` inputs retain their method, headers and body through cloned attempts after origin validation.

## Verification

`tests/session.test.ts` uses fake fetch responses to cover login, positive-integer session lifetimes including values above one day, the exact 16 KiB JSON-body boundary, CSRF bootstrap, refresh, same-client single-flight behavior, and independent clients sharing one same-origin exclusive Web Lock for sign-in, refresh, and logout. The cross-client regression holds sign-in and refresh response parsing and the logout response open while a sibling mutation queues, and asserts that CSRF bootstrap and every cookie-mutating request remain inside the lock. The suite also covers serialized concurrent sign-ins, one retry including replay of a consumed body-bearing `Request`, pre-aborted and in-flight caller cancellation, prompt cancellation while awaiting a shared refresh without canceling that refresh, cancellation before retry dispatch, native-`Response` preservation, token clearing after a rejected retry, stale-result invalidation, a later successful sign-in, preservation of a queued sign-in, retry invalidation after a cleared session, same-origin checks for string/URL/Request destinations before fetch and again before retry, logout cleanup including a late-refresh race, delayed sign-in invalidation, malformed responses and storage privacy without a live backend. A manual two-tab in-app browser smoke additionally verifies that both contexts restore after concurrent reloads; it is not automated browser acceptance.
