# `package-lock.json`

Source: [`../package-lock.json`](../package-lock.json)

## Purpose

This npm lockfile is the reproducible dependency graph for `package.json`. It uses lockfile version 3 and records the exact package versions, registry URLs, integrity hashes, dependency relationships, licenses, and root runtime constraints resolved for the frontend.

The root package entry mirrors the direct dependencies and development dependencies in `package.json`, including the Node.js `>=24.15.0 <25` engine range, jsdom `30.1.1` as the DOM test environment and `@playwright/test` `1.63.0` for the browser suite. Playwright adds only `playwright` and `playwright-core` `1.63.0` and no browser download; its specs drive the installed Chrome and Edge. The lockfile is consumed by `npm ci`, which is the preferred install command for repeatable local and CI builds.

The current root entry pins `next` and `eslint-config-next` to `16.3.6`, matching `package.json`. Keep these resolved versions synchronized with the manifest when updating the frontend framework.

## Maintenance boundary

Do not hand-edit individual transitive entries. Change `package.json` deliberately and regenerate the lockfile with the pinned npm tool, then review both files together. A lockfile change can alter build or security behavior even when application source is unchanged.

## Verification

`npm ci` validates that the manifest and lockfile agree. `npm run verify` then checks the installed graph through linting, TypeScript, unit tests, and the production build.
