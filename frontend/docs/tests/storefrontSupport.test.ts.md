# Storefront browser-helper unit tests

`tests/storefrontSupport.test.ts` validates the Ticket 17 end-to-end helpers without a running application or PostgreSQL. Display cases cover `taka` grouping (`৳0.01` to `৳1,234,567.50`, no space), percentage and flat badges, `Page n of m`, singular and plural product counts, the page title template, absolute canonical URLs and whitespace normalization. `copyPattern` matches either apostrophe, anchors both ends and escapes regular-expression characters. The MRP label shows only when the MRP is strictly above the current price, and `paisa` rejects non-canonical money. An empty category counts as one page.

Ordering cases prove that `orderedNames` yields distinct lower-case names whose byte order differs from the public order, that `publicOrder` restores them from any order and breaks equal names by id, and that the bar takes the first eight categories. Malformed-id fixtures include an upper-case UUID and off-by-one lengths.

Contract-guard cases accept consistent plain, percentage and flat prices and reject a wrong saving, a saving without a discount, a FLAT value that differs from the saving, an MRP below the selling price and a leaked `productId`. Cards reject staff fields, upper-case ids and image URLs outside the public image route. Page guards reject a wrong item count, a wrong page size and duplicate ids, and accept an empty page. Details accept the equipment and inactive-category nulls and reject a leaked `active`. Stubbed responses prove that `expectPublicJson` requires no-store, a valid request id, no cookie and the expected status, and that `expectPublicNotFound` requires the exact envelope with matching header and body request ids, rejecting malformed and overlong ids even when both match.
