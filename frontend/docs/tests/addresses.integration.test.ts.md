# Real saved-address client integration

Exercises registration and password sign-in against the isolated test API, then calls the production address client through its public session boundary. A fresh synthetic User creates three addresses, receives the bounded capacity refusal, reloads server order, edits the default, removes it and observes the oldest remaining address promoted with its version incremented. The returned allowance proves creates and edits count while removal does not.

Run `npm run test:integration` with `MEDI_WISH_API_URL` set to the task-owned API. The existing test harness owns the temporary database schema and cleanup; no development database or real personal data is used.
