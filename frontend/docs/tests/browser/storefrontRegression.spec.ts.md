# `tests/browser/storefrontRegression.spec.ts`

Source: [`../../../tests/browser/storefrontRegression.spec.ts`](../../../tests/browser/storefrontRegression.spec.ts)

Ticket 17 T6 browser regression suite (plan T6 "Browser"). It runs against the real API jar and PostgreSQL in both `chrome` and `msedge`, uses only synthetic data from `catalogSupport.ts`, `discountSupport.ts`, `productImageSupport.ts` and `storefrontSupport.ts`, and seeds its own data in each test. It never asserts the whole category list: header-bar checks compare against the first 8 entries of `GET /api/categories`, read just before the page load.

Every test has the tags `@t17`, `@t17-T6`, `@t17-ui` and `@regression`. The E2E-17-15 tests also have `@cross-14-17` and E2E-17-17 has `@cross-16-17`.

| Test id | What it proves |
| --- | --- |
| E2E-17-12 (JavaScript on) | The four `injection` strings (Product name, description, category name, image alt) appear literally in the category `h1`, the card, the breadcrumb, `document.title`, the meta description and the image `alt`. No dialog opens, `window.__t17` stays unset, and `main` holds no `script`, `svg[onload]`, `img[src=x]`, `b` or inline handler created from the data. |
| E2E-17-12 (JavaScript off) | The `serverHtml` title, meta description, `h1`, card names and main text are literal. The raw HTML holds none of the injected markup prefixes. In a context with JavaScript disabled, the breadcrumb link and the image `alt` are literal and no injected element exists. |
| E2E-17-13 (Product) | Inactive, unpriced, unknown and every `malformedIds` Product URL (upper case included) return 404 with the not-found page and identical visible `main` text, page title and meta description. The header is excluded because its session-dependent links load after first paint. A listed Product renders as the control. |
| E2E-17-13 (category and page) | Inactive, unknown and malformed category URLs, and the page values `2` (past the end), `0`, `-1`, `abc`, `01`, `1.5`, an empty value and a repeated value, return 404 with the same visible `main` text and metadata as an unknown Product. |
| E2E-17-14 | `main` holds no button, input, select or textarea on a category page or on a details page without images. On a details page with two images, the only buttons are `Image 1` and `Image 2`. No `main` text matches `/stock\|availab\|add to cart/i`. Links in `main` cannot advertise a purchase action by accessible name or point to a cart or checkout URL, including icon-only links. |
| E2E-17-15 (Product) | An Admin rename, a Sale Unit change and a selling-price change each show after the next `page.reload()`. Deactivation turns that reload into 404, and the category page then lists only the remaining Product. |
| E2E-17-15 (category) | A category whose name starts with digits (`000 Bar …`), so it sorts into the first 8, appears in the header bar. After the Admin deactivates it, the next load shows the bar equal to the new first 8 without it. |
| E2E-17-16 | `Authorization: Bearer invalid` leaves every public API body unchanged (including 404 bodies, compared without `requestId`). The server HTML of the details and category pages holds no `"version":`, `updatedBy` or `"status"` key with a `ProductStatus` value (`ACTIVE`, `INACTIVE`, `NEEDS_PRICE`), whether plain or backslash-escaped. The root layout ships every message namespace to the client, so the translated label `"status": "Status"` is present in every page and is not a staff field. The first two checks run serially. A separate last test seeds its own category and Product, reads them through the server-rendered details and category pages and then the public API, waits (`expect.poll`) until the log holds that last read's `HTTP response status=200` line with its `X-Request-ID` as `requestId`, and checks that `apiLog()` contains none of that text nor any other unique catalog text seeded by this worker, so it holds when run alone. The worker text includes generated category names from the not-found and purchase-surface cases, Product names created for the privacy checks, and the scheduled Discount fixture's unique names. |
| E2E-17-17 | A Category percentage and a Product flat Discount that start `dhakaTomorrow()` change no public price and show no badge and no struck price, on the category page, on the details pages or in the server HTML. `assertAwayFromDhakaMidnight()` runs in `beforeAll`. |

Targeting: `--grep @t17-T6`, `--grep @regression`, `--grep "E2E-17-13"`, `--grep @cross-14-17`.

Local helpers: `seedInjected`, `expectNoInjectedMarkup`, `withoutJavaScript` (runs a check in a context with JavaScript disabled), `notFoundViews`, `expectNoPurchaseLinks` and `remember` (collects seeded text for the log check).

Status: written test-first, then run against the Ticket 17 build. The first run had 13 failures (duplicate card links, the staff-status false positive and the header-timing comparison). The fixes are described above; the @t17 run after them passed (see the Ticket 17 evidence file).

On 2026-10-23 (`73eeaa9` plus working tree) the change (self-seeding API-log check in E2E-17-16, its correlated log marker and retitle) passed ESLint and `tsc --noEmit`, then ran with `TEST_DB_HOST=127.0.0.1 TEST_DB_PORT=55433` (PostgreSQL 18 UTF8) and a jar rebuilt from that tree: `npx playwright test tests/browser/storefrontRegression.spec.ts tests/browser/storefrontA11y.spec.ts --grep "E2E-17-1[69]"` passed 14 of 14 (7 per Chrome and Edge project); no browser roles or schemas were left and ports 18115 and 3115 were freed.
