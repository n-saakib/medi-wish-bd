# `tests/browser/storefrontPages.spec.ts`

Source: [`../../../tests/browser/storefrontPages.spec.ts`](../../../tests/browser/storefrontPages.spec.ts)

Ticket 17 T5 page specs. They test the server-rendered storefront (plan §4.0.5) on the built Next server (`127.0.0.1:3115`) against the real jar and PostgreSQL. Server HTML is read with JavaScript disabled, through `serverHtml()` and the local `withServerPage()`, so everything asserted there came from the server (AC3). Journeys run with JavaScript on. Locators come from `storefront(page)` (roles and the plan's fixed classes), and copy comes from `storefrontCopy`.

A shared fixture is seeded once per worker in `beforeAll`: 25 medicines (selling ৳150.00, MRP ৳160.00, description `Line one\nLine two`, review required) and a 10% Category Discount. If a test fails, the worker restarts and seeds again, so the other tests still run.

Acceptance IDs:

- **E2E-17-05**, server HTML without JavaScript:
  - Home: HTTP 200 and an absolute canonical for `/` on the configured site origin.
  - Category page: title `{name} · Medi Wish`; canonical `http://127.0.0.1:3115/categories/{id}`; meta description `{name} at Medi Wish: 25 products.`; card names equal the API names in order, and each card link points to its matching API Product id; each card shows `.price`, a struck `s.price-was` and a `.badge-sale` from `taka()`/`badgeText()`; pager links.
  - Page 2: canonical ends `?page=2`, it holds the 25th card with its matching Product link, and Previous goes to the bare URL.
  - Details: title, meta description (collapsed plain text), canonical, exactly one price, struck selling price, `10% OFF`, a `MRP ৳160.00` label that is neither `<s>`/`<del>` nor inside one and has no line-through decoration on itself or an ancestor, the review note, the breadcrumb (Home and category), the About rows in order, and the description newline in both source text and visible `innerText`.
  - `/categories`: every tile equals the API list in order, and 9 own categories are seeded so there are more than the bar's 8.
  - V-7: counts `apiResponseCount()` around one `request.get` of a details page, expecting at least 2. The count is attached as `v7-api-reads.json`. A count above 2 is recorded as a `V-7 cost` annotation, not a failure.
- **E2E-17-06** (`@cross-15-17`): fetches category and details API views for the same Products, verifies each category-card image equals that Product's first public details image, then compares the JavaScript-disabled SSR card image URL/alt and ordered details gallery URL/alts directly with those API values. Images use `/_next/image?url=<public API image URL>` and answer `200 image/webp`; null alts fall back to `{name}, image {n}`. A card or details page without images shows the `[role="img"]` placeholder. The gallery renders the first image large and checks two `aria-pressed` buttons.
- **E2E-17-07**: guest journey `/` → `/categories` → own category → **Next** → page 2 → a Product → reload, with the same `main` text after the reload. The home grid shows the first 8 names of `GET /api/categories`, and the bar shows those 8 plus "All categories". No browser request carries an `Authorization` header. A second case checks the bar's page-declared current mark with JavaScript on: on `/categories` only All categories has `aria-current="page"`; on page 1 of the first bar category only its link has `aria-current="page"` and `is-active`, as does the breadcrumb category link; after a card click to one of its Products that link has `aria-current="true"`, the breadcrumb shows Home and that category, and no breadcrumb link has `aria-current`; on the fixture's `?page=2` the breadcrumb link has `aria-current="true"` (the fixture category usually sorts after the bar's first eight, so the bar's `true` mark on later pages is unit-tested in `StorefrontComponents.test.tsx` instead); and on that first category's `?page=99` (404) no bar link has `aria-current` or `is-active`. Absence is asserted only after `hydrated()` sees React's fiber on the bar link (a React internal) and the network is idle. That gives the client mark time to appear, but it is a timing heuristic rather than a guarantee.
- **E2E-17-08**: `?page=1` answers `307` with a `Location` that resolves to `/categories/{id}`. `?page=3` (past the end), `0`, `abc`, `-1`, `01` and `2.0` answer 404 and show the not-found page.
- **E2E-17-09**: unknown, inactive, malformed (text, short, long, braces) and upper-case Product URLs, and an inactive category URL, answer 404 (`request.get`, V-4). Each shows the not-found copy with a home link, the store header and the category bar, and the `normalizedMain` text is identical for all of them. A second case checks unmatched URLs served by the root `not-found.tsx` (`/products/{id}/x` and `/no-such-page-{token}`): each answers 404 and shows the banner's `Medi Wish` Logo link to `/` and the shared not-found title and text (plan P14). It has no category bar, so that is not asserted.
- **E2E-17-10**: an empty active category answers 200 with the empty state and a "Browse categories" link, and shows no cards or pager. A Product of an inactive category answers 200 with a breadcrumb of only "Home", and its Category Discount still applies; the price equals `publicPrice()` (`@cross-16-17`).
- **E2E-17-11** (`@cross-03-17`): a Customer who signed in through `/register` and a guest in a separate context get identical `main` text on a details page. Only the signed-in header shows the username, and that account link opens `/account`.

Tags: `@t17`, `@t17-T5`, `@t17-ui`, plus the cross tags above, which only the tests that cross another story carry. Target the file with `npm run test:browser -- --grep "@t17-T5"` (with the API file) or `--grep @t17-ui`, or one behaviour by id, for example `--grep "E2E-17-08"`.

Local helpers: `withServerPage` (a page opened with JavaScript disabled), `target` (an href resolved against the page URL), `hydrated` (waits for React hydration and network idle), `mainText`, `uploaded` and `expectWebp`.
