# Synthetic product image fixtures

`tests/browser/imageFixtures.ts` builds deterministic, dependency-free RGB PNGs with valid IHDR/IDAT/IEND chunks, DEFLATE pixels and CRC-32 checksums. `pngFixture(width,height,seed)` changes real pixel content for conflict and concurrency cases; its dimensions and total pixels are bounded to keep test memory predictable.

`validPng()` is 32 × 24. `validJpeg()` embeds an 8 × 6 synthetic JPEG generated by JDK 25 ImageIO, with no personal metadata. `largePng()` contains roughly 2.7 MB of real noisy RGB pixels, so large-body authentication tests cross Tomcat's former 2 MB swallow bound and still fit the accepted 3 MiB input/output policy. `oversizedPng()` is exactly 3,145,729 bytes. `oversizedDimensionsPng()`, `textAsPng()` and `invalidUploads()` supply dimension, truncated/undecodable, declared-type, extension and disallowed-format refusals.

`pngSignature`, `pngCrc32` and `maxImageBytes` support independent fixture integrity checks in `tests/imageFixtures.test.ts`. These bytes are synthetic test inputs, never image storage or a production encoder.

`pngWithMetadata(marker)` inserts a valid PNG tEXt chunk and appends the same marker after IEND. `jpegWithExif(marker)` inserts a valid minimal EXIF TIFF APP1 segment. Real ImageIO decoding verifies these remain valid images; the API tests require re-encoding to discard their markers.

Complete synthetic 2 × 2 `validGif()` and `validWebp()` fixtures were generated and decoded on native Windows with sharp; both declared and PNG-disguised variants exercise actual-type refusal. `corruptPixelsPng()` retains complete IHDR/IDAT/IEND framing and valid CRCs around an invalid DEFLATE block. `outputOversizedPng()` is a valid 1024 × 1023 input (3,144,702 bytes) that native Windows JDK 25.0.4.1 re-encodes to 3,145,842 bytes, independently crossing the 3 MiB stored-output cap.

The JPEG refusal matrix also covers JPEG bytes declared PNG, JPEG with PNG extension, truncated JPEG and `corruptPixelsJpeg()`. The latter preserves full JPEG segment framing, SOF dimensions and EOI while placing an illegal second SOI marker in the pixel scan; JDK ImageIO independently reads its 8 × 6 header and fails pixel decoding.

`rgbaPng()` is a minimal 3 × 2, 8-bit PNG color type 6 fixture with transparent, three partially transparent and two opaque pixels. Its primary-color alpha pixels avoid browser premultiplication rounding while still detecting rejection or flattening of accepted PNG transparency.

The shared invalid-upload matrix retains combined MIME/extension failures and adds correctly named complete PNG/JPEG bytes declared as the other allowed MIME. Those isolated MIME failures are consumed by both append and replacement rejection loops; extension rejection cannot mask omitted declared-MIME equality.
