E2E-12-05,16,59–61,63,70,73,76–78,93,94 record command intents while allowing the established one-time authentication retry. An actual 401 remains counted while refresh is pending and no following command exists. Once the retry arrives, request identity links its recorded response; method, full URL (including version query) and raw body must remain identical, and another 401 is refused. Only then is the first 401 excluded. Every other dispatch, including transport failures, still counts, so ordinary duplicate commands cannot pass. E2E-12-74 exercises this recorder alongside its existing strict two-request/one-refresh assertions and requires exactly one effective create intent. Response callbacks only record status against the exact Request object; assertions run at explicit test checkpoints. Raw dispatch assertions remain unchanged for the deliberately injected first-401 journey (E74), revoked session (E75), and zero-dispatch-only checks.
