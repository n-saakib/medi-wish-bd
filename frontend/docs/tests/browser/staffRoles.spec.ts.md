# `tests/browser/staffRoles.spec.ts`

Source: [`../../../tests/browser/staffRoles.spec.ts`](../../../tests/browser/staffRoles.spec.ts)

## Purpose

Ticket 08's end-to-end browser tests: the **Users and roles** pages (`/admin/users` and `/admin/users/<id>`) and what a role change does to the target's open browser, on the `chrome` and `msedge` projects. Every User holds exactly one role, chosen on the detail page with one **Role** radio group and a **Save role** button (DECISIONS S6). Staff sign in and enroll through the pages with the [`support.ts`](support.ts.md) helpers; a second person uses `browser.newContext()`, or [`apiSession.ts`](apiSession.ts.md) when only the API matters. Every visible string is fixed in §10 of the Ticket 08 implementation plan, which also lists each test's ID, tag and acceptance criterion.

## Tests by sub-ticket tag

- **`@t08-T5`** (`E2E-08-29`–`43`, `E2E-08-53`, `E2E-08-54`): the StaffHome link for Admins only; the journey (search, sent as the `POST /api/admin/users/search` body and never in a URL, open, select **Moderator**, **Save role**, the exact `PUT` body `{ role, rolesVersion }`, the success status and "Changed from Customer to Moderator" history row, a reload, and the target's browser sent to sign-in and then to authenticator setup, landing on `/staff` as `Moderator`); the Moderator's access-denied state; the guards for signed-out visitors, Customers and restricted staff; list search, the exact-role filter, empty state and paging (`Showing 1–20 of 21`); the disabled options and their text reasons (the **Admin** option, another Admin's row, the own row, the Super Admin's row); the Super Admin making a Customer an Admin and back; the stale alert with **Reload**; the refused alert; the not-found state (no API call for a malformed id); `no-store` on guarded list/not-found pages, awaited before the next document navigation; one request for a double click; the generic error for a failed search and a failed detail load, each recovered by loading again (the detail page shows no **Role** card meanwhile); a save that fails before reaching the server, which clears **Saving…**, changes and revokes nothing, and applies once on retry; demotion of a verified Moderator to Customer and re-promotion; **Delivery person** without MFA; and a history entry whose actor no longer exists, read as "by a deleted account" (the actor is cleared with [`clearRoleChangeActors`](apiSession.ts.md), as `ON DELETE SET NULL` would).
- **`@t08-T6`** (`E2E-08-44`–`45`, `E2E-08-55`): an Admin demoted to Customer while the detail page is open is sent to sign-in and changes nothing; privacy: every username, mobile, email and password of two synthetic Users and of the acting Admin, the Admin's authenticator key, and the search term, is checked, raw and percent-decoded (`percentDecoded`: `%40`, `+`, double encoding), against every outgoing request URL (`page.on('request')`, any host), the page URLs, storage and `history.state`, the console and the API log, and everything but the usernames also against the page text (the pages show usernames by design); a save whose response is lost after the server committed it (`loseNextResponse`: `route.fetch()`, then `route.abort()`; it returns `{ committed }` once the route is installed, and the test awaits `committed`, the server's status, only after pressing **Save role**) shows the generic error and clears **Saving…**, and the retry from the page sends the same `{ role, rolesVersion: 0 }` and gets the `200` no-op: one audit row, and the target's session opened between the two stays active.
- **`@t08-T7`** (`E2E-08-46`–`48`): the `@smoke` test (an Admin sets Moderator; a Customer opening `/admin/users` lands on `/account`), and at 375 px and 1280 px, waits for the ready page before deliberately reloading and awaiting it again (so an in-flight bootstrap refresh is not interrupted), then checks no horizontal scroll, labelled inputs, a focus ring on every Tab stop (the radio group is one stop), 44 px targets in `main`, the Admin reason as the radio's description, and keyboard-only search, open, choice with the arrow keys and save.
- **`@t08-T8`** (`E2E-08-49`): the plan §1 demo script in two browsers, ending with a Moderator's `PUT` refused with `403 ACCESS_DENIED`.

## Running

Build the backend jar first, then run one gate at a time, for example `npm run test:browser -- --grep @t08-T5`. `npx playwright test --grep @smoke` runs `E2E-08-46` with the Ticket 06 smoke test.
