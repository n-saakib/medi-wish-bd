# Storefront end-to-end support

`tests/browser/storefrontSupport.ts` owns the Ticket 17 public wire contract (plan §4.0.1) independently of production code. `PublicCategory`, `PublicCategoryPage`, `PublicCard`, `PublicProduct`, `PublicImage`, `PublicPriceView` and `PublicDiscount` are the accepted shapes. The sorted key-set constants (`publicCategoryKeys`, `publicCardKeys`, `publicProductKeys` / `publicDetailsKeys`, `publicImageKeys`, `publicPriceViewKeys`, `publicDiscountKeys`) reject any extra field, so a staff field such as `version`, `status` or `productCount` fails the read. `staffOnlyFields` lists the names that must never reach public JSON or HTML.

`expectPublicJson` checks status, `Cache-Control: no-store`, a bounded `X-Request-ID`, a JSON content type and no `Set-Cookie`. `expectPublicNotFound` requires the exact three-key `404 NOT_FOUND` envelope, a bounded header request id matching the body's id, and returns the body without `requestId`, so callers can prove that inactive, unknown, malformed and past-the-end cases look the same. The shape guards check lower-case UUIDs, field bounds, the image route, page arithmetic (`items.length = min(24, totalItems − page·24)`), unique ids and price consistency in integer paisa: price plus saving equals the selling price, a FLAT value equals the saving, and the MRP is never below the selling price. They never pick a winning Discount.

`publicApi(http)` sends raw anonymous requests to the three routes; the `page` value is passed through unchanged, so invalid values can be tested. `publicCatalog(http)` returns validated reads; its `categories()` also asserts the public order. `withoutProductId` turns the Ticket 16 price body into the expected embedded `price`.

`seedCategory` creates an active category with active, priced Medicines through the real staff routes, named by `orderedNames`. Those names share a prefix and use two-letter codes whose first letter alternates case, so `lower(name)` order differs from byte order under every collation. `publicOrder` reproduces the public order: `lower(name)`, then id. `seedEquipment`, `unknownId` and `malformedIds` (including an upper-case UUID that the storefront must reject) cover the remaining fixtures. Every name carries a `token()`, so data from parallel suites never collides.

`serverHtml(browser, path)` reads a page in a fresh context with JavaScript disabled. It returns the status, title, canonical link, meta description and robots, h1 texts, normalized `main` text, card names and raw HTML, so assertions see only what the server rendered. It never waits for an element, so a page that lacks `main` (such as a framework 404 before the pages exist) fails on the caller's status check at once instead of timing out. The home Categories section is located by its "Categories" heading, because the plan does not require a labelled region. `apiResponseCount()` counts the harness API's request status lines for the V-7 measurement; `apiLog()` exposes the log for privacy checks.

`storefront(page)` locates the planned markup by role and accessible name: the `Categories`, `Breadcrumb` and `Pagination` navigations, cards (`article`), the About region, the review note, gallery thumbnails (`Image {n}`), not-found and error headings, and the planned price classes (`.price`, `s.price-was`, `.badge-sale`, `.mrp-label`). `storefrontCopy` holds the exact English messages. `copyPattern` accepts a straight or typographic apostrophe, because the repository's messages use `’`. `taka`, `badgeText`, `pageOf`, `productCount`, `pageTitle`, `canonical`, `pageCount` and `firstCategories` build the expected visible text. `watchForInjection` fails a test when an injected string opens a dialog or sets `window.__t17`.

Pure helpers are covered by `tests/storefrontSupport.test.ts`.
