# Discount database end-to-end specifications

`tests/browser/discountDatabase.spec.ts` exercises the live browser-run PostgreSQL schema alongside real Admin HTTP commands. Every SQL helper verifies the run-owned schema; fixture UUIDs are validated before interpolation. Mutation probes use `rolledBackSql` so rejected constraints and deletion tests leave no data behind. Native `@t16` / T4, T5 and T6 tags keep these checks selectable with the rest of Ticket 16.

The schema case checks the two planned tables, Discount columns and numeric scales, required version, date/timestamp types, all four named indexes (including Product/Category partial predicates), and changeset `016-discounts`. Named check probes assert SQLState 23514 for invalid target/kind/value pairings, whole-percent range/truncation, nonfinite values, amount range, date order and audit event type. Numeric overflow uses SQLState 22003.

FK probes isolate Discount references from existing Product audit/category references. A Category fixture has no Products; deleting its Discount and audit inside the rollback probe permits deleting that Category. Product audit rows are removed only inside the rollback probe before testing the Discount's Product FK. Discount audit itself pins the Discount. All three DELETE probes require SQLState 23001 for ON DELETE RESTRICT, matching the actual PostgreSQL 18 server result in the backend migration checks; the prepared 23503 expectations were corrected without relaxing table-name assertions or rollback isolation.

Create/edit/end checks fingerprint every unrelated table and the complete Product row, while asserting one audit event per command, the actor and request-id header. A scheduled PERCENTAGE fixture changes kind/value and both dates before End now; each persisted audit independently matches the expected kind, paired percent/amount values and date window. Complete earlier audit rows remain identical after subsequent mutations and identical stale update/End retries, whose full-table fingerprints prove no writes. Each audit timestamp must equal its real mutation response’s `updatedAt` as a PostgreSQL instant at persisted TIMESTAMPTZ precision, without depending on timestamp spelling or timezone. Lost-response replays and unchanged stale PUTs produce neither new rows nor new audit. Derived Product history is never persisted; distinct synthetic end instants and captured stored entries establish the exact newest twenty merged events, rather than merely checking length and sorting; the existing Product change check refuses both derived event types.

Historical, tie and latest-history tests backdate only their own synthetic Discount rows directly in the isolated schema: one proves today-inclusive end dates, past-date replay, date-ended status and Dhaka event timestamps without writes; one proves earlier-start then UUID-string tie ordering. The production calendar stays unchanged. These tests complement the required controlled-calendar Java integration tests; they do not replace boundary-crossing or restart evidence.

Run with the plan's built-jar, UTF8-cluster browser harness. No tests skip an absent schema or feature: these checks intentionally fail until the accepted migration and Discount implementation exist.

The newest-twenty oracle independently requires the fixture’s three stored CREATED, PRICE_CHANGED and ACTIVATED rows, Admin actor and exact stored price/validation values before merging. The final comparison retains every stored and derived field, normalizing only a trailing all-zero timestamp fraction on both actual and expected events because Java Instant omits it. Nonzero fractional precision, exact event membership and order remain checked. The Dhaka-midnight guard runs before each test fixture.

Whole-percent probes include in-range fractional 1.50 and 98.50, which fail specifically on ck_discounts_percent_range; valid integer endpoints 1 and 99 succeed in rollback probes. The historical date-ended fixture proves its 30% price before backdating and fresh public/staff fallback to the original 10% afterward, without persisting derived read events.
